# Инструкции для AI-агента

## Назначение проекта

React resume — персональный сайт-резюме Никиты Рыхлова, доступный на
https://rykhlov.tech. Это статическое одностраничное приложение без backend:
React 18, TypeScript в strict-режиме, Vite 7, SCSS. Поддерживаются русский и
английский языки, светлая и тёмная темы, скачивание PDF-резюме на обоих языках.

## Порядок работы

- Перед изменениями прочитай относящиеся к задаче файлы и проверь `git status --short`.
  Сохраняй существующие незакоммиченные изменения; не откатывай чужую работу.
- Ограничивай изменения задачей. Не добавляй библиотеки, backend, роутер или новую
  систему стилей ради локальной правки.
- Используй npm и существующий `package-lock.json`. Для установки зависимостей
  из lock-файла используй `npm ci`.
- Отвечай на языке пользователя. В отчёте указывай изменения, выполненные проверки
  и конкретные ограничения, если что-то не удалось проверить или сгенерировать.
- Не публикуй сайт и не отправляй изменения в remote без запроса пользователя.

## Контент и достоверность резюме

- Добавляй только подтверждённые пользователем факты. Не выдумывай работодателей,
  даты, технологии, размер команды, метрики, награды или обязанности.
- Не переноси в публичное резюме сведения из личного контекста без указания
  пользователя включить их. При противоречии в существенных фактах уточни данные.
- Изменения текста сайта вноси в обе версии `en` и `ru` в `src/i18n/content.ts`.
  Переводы должны совпадать по смыслу, датам, числам и уровню ответственности.
- Пользовательские тексты новых элементов размещай в типизированном контенте;
  не размножай языковые условия и строки по компонентам.
- При изменении стажа проверяй `hero.years`, первый абзац `about`, `metrics`,
  тексты CV и SEO-описания в `index.html`. Не суммируй пересекающиеся периоды.
- Сохраняй обратную хронологию опыта. Не заполняй отсутствующие стек, достижения
  или команду вымышленными данными; скрывай пустые блоки, как у фриланса.
- При изменении контактов проверяй `socials`, `contact`, `COPY_EMAIL`,
  `COPY_PHONE` и данные PDF. Пути скачивания задаются в `cvFiles`.
- Количество компаний и другие сводные показатели проверяй по смыслу:
  запись о фрилансе сама по себе не увеличивает число продуктовых компаний.

## PDF-резюме

- Сайт и PDF используют разные данные. Изменение `src/i18n/content.ts` не меняет
  PDF; при обновлении фактов резюме синхронизируй `scripts/build-cv.mjs`.
- README и комментарии генератора ссылаются на `../resume/resume.md` и
  `../resume/resume.ru.md`. Эти файлы не входят в данный репозиторий: не считай их
  доступными автоматически и не изменяй соседний проект без соответствующей задачи.
- Запускай `npm run cv` для генерации обоих PDF в `public/cv/`. Нужен установленный
  Chrome/Chromium; путь можно передать через `CHROME_BIN=/path/to/chrome npm run cv`.
- Сохраняй ATS-ориентированную структуру: одна колонка, выделяемый текст,
  последовательный порядок чтения и обычные маркеры списков. Используй существующий
  renderer для экранирования текста и inline-разметки.
- После генерации проверь оба файла: наличие нового текста, переносы страниц,
  отсутствие обрезанного текста и пустых заголовков. При доступности PDF-просмотра
  проверь визуально, особенно после изменения шаблона или объёма текста.
- Если браузер завершился с ошибкой, явно сообщи, что PDF не пересозданы.
  Успешная сборка Vite не подтверждает актуальность скачиваемого резюме.

## UI и код

- Следуй существующему стилю: функциональные React-компоненты, типизированные props,
  общие типы из `content.ts`, SCSS-классы с BEM-подобными именами.
- Используй существующие CSS-токены. В `src/index.tsx` файл `colors.css` должен
  импортироваться после `typography.css`: у них пересекается имя `--text-body`.
- Тема задаётся через `data-theme` на корневом HTML-элементе. Ключи localStorage:
  `nr_theme` и `nr_lang`. Логику начальной темы в `index.html` и `usePrefs.ts`
  поддерживай согласованной, чтобы не появлялась вспышка другой темы.
- Для навигации используй `scrollToId` / `scrollToTop`, а не `scrollIntoView`.
  При изменении высоты навигации проверяй её фактический отступ при прокрутке.
- Новые иконки добавляй в `IconSprite.tsx` и union `IconId`; используй `Icon`.
- Сохраняй управление с клавиатуры, видимый фокус, подписи кнопок и корректный
  `aria-expanded` у аккордеона. Не используй кликабельный `div` вместо кнопки.
- Учитывай `prefers-reduced-motion`. Effects должны очищать подписки и анимации
  и корректно работать при повторном запуске в React StrictMode.
- При добавлении секции согласуй её ID, навигацию, порядок в `App.tsx` и переводы.

## Проверка и команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Локальный Vite-сервер (`npm start` — эквивалент) |
| `npm run build` | Проверка TypeScript и production-сборка в `build/` |
| `npm run preview` | Просмотр уже собранного сайта |
| `npm run cv` | Отдельная генерация EN/RU PDF через системный браузер |
| `npm run deploy` | Публикация `build/` через gh-pages; predeploy запускает сборку |

- После изменений кода или контента запускай `npm run build` и `git diff --check`.
  Для изменений только документации достаточно проверки diff и точности инструкций.
- В проекте нет настроенных npm-команд тестов или линтера. Не сообщай об их
  успешном прохождении и не добавляй тестовый framework ради текстовой правки.
- UI-изменения проверяй на узком мобильном и широком экране, на EN/RU и в обеих
  темах. Для затронутых элементов проверяй навигацию, аккордеон, копирование
  контактов и скачивание PDF правильного языка. Укажи, если браузерная проверка
  была недоступна.
- Не редактируй `build/` вручную: он генерируется и игнорируется Git. Сохраняй
  `outDir: 'build'` согласованным с deploy-скриптом. Не меняй домен и файлы
  `public/CNAME` / `public/_redirects` без задачи на настройку хостинга.
